# GitHub Copilot CLI worker verification

Audience: maintainer verification.

Verified 2026-09-25 and 2026-09-26 on macOS arm64 with `GitHub Copilot CLI 1.0.88`.
The [adapter reference](../../.agents/skills/harness-adapters/references/harness/copilot.md) owns operating facts; executable owners carry launch and state mechanics.
This verification covers crewmates and scouts on the tmux backend.
Primary, secondmate, Herdr, Zellij, Orca, and cmux integration are outside this guarantee.

## Refresh commands

```sh
copilot --version
copilot --help
bin/fm-test-run.sh tests/fm-copilot-harness.test.sh
FM_COPILOT_SIGNALS_LIVE=1 bin/fm-test-run.sh tests/fm-copilot-signals-live-e2e.test.sh
FM_COPILOT_SIGNALS_LIVE=1 FM_COPILOT_LIVE_CMD=/opt/homebrew/bin/copilot bin/fm-test-run.sh tests/fm-copilot-signals-live-e2e.test.sh
```

The credentialed guard submits real prompts on the signed-in account, uses a private tmux socket, and runs the actual command generated by `fm-spawn.sh`, keeping the operator's real home so Copilot's sign-in is available.
`FM_COPILOT_LIVE_CMD` writes that value into the isolated home's `config/copilot-cmd`, so the second invocation proves a configured launch command replaces the executable prefix end to end.
Worktree allocation and initial endpoint delivery use the portable fixture; steering, skill invocation, interrupt, and exit use the real control plane and vendor process.
Failures name the installed Copilot CLI version.

## Observed vendor surfaces

`copilot --version` printed `GitHub Copilot CLI 1.0.88.`, including when run through a configured launch command that prints its own lines first.
`--help` lists `-i, --interactive <prompt>`, `--plugin-dir <directory>`, `--allow-all`, `--no-ask-user`, `--model <model>` (with `auto`), and `--reasoning-effort <level>` with `none, minimal, low, medium, high, xhigh, max`; it no longer lists the `--effort` alias that 1.0.68 printed beside `--reasoning-effort`.
`copilot help environment` documents that `COPILOT_ALLOW_ALL` set to exactly `true` also trusts the working directory.

A probe plugin mounted with `--plugin-dir` logged this ordered sequence for a tool-using turn launched with `-i`:

```text
userPromptSubmitted
sessionStart
preToolUse
postToolUse
agentStop stopReason=end_turn
```

Hook commands ran with the plugin directory as their working directory, inherited the launch environment, and received `COPILOT_PROJECT_DIR` set to the workspace.
`/exit` fired `sessionEnd` with `reason=user_exit` and printed `copilot --resume=<session-id>`.
The same plugin shape and `COPILOT_ALLOW_ALL=true` ran a prompt with no trust dialog on the CLI packages that reported `1.0.66-0`, `1.0.69-1`, and `1.0.70-0`, with `userPromptSubmitted` and `agentStop` firing.

A turn in which the model started a background shell and replied without waiting fired `agentStop` while the status row still read `Waiting for background shells · <bytes> esc interrupt`.
When the shell finished, Copilot submitted its own follow-up, which fired `userPromptSubmitted`, a `notification` hook, and a second `agentStop`.

A running turn renders a status row such as `◉ Working · 97 B esc interrupt`; the idle row reads `← open sidebar · / commands · ? help · tab next tab`.
The idle composer is a bare `❯` between horizontal rules with no placeholder text.
One `Ctrl+C` on a running turn marked the running shell tool `Operation aborted by user` and returned the idle row with an empty composer, with no hook firing.
An `Escape` sent through tmux `send-keys` did not cancel the turn, twice in a row.
One `Ctrl+C` on an idle agent rendered `ctrl+c again to exit` and then returned to the idle row.

Without `COPILOT_ALLOW_ALL=true`, a fresh folder stopped on a `Confirm folder trust` box asking `Do you trust the files in this folder?` with options `1. Yes`, `2. Yes, and remember this folder for future sessions`, and `3. No (Esc)`, even with `--allow-all`.

A worker that wrote its own commit message passed `-m "Co-authored-by: Copilot ..."`; the per-task git hooks path stripped it, and the landed commit carried no co-author trailer.

In tmux the pane's foreground process group contained a process whose `ps -o comm=` was the versioned install path ending in `/copilot`, both for plain `copilot` and for a configured launch command.

## Coverage and limits

The portable regression pins anchored liveness, worker-only resolution, the single Ctrl+C interrupt and `/exit`, each delivery signal independently, draft safety, the trust-dialog pairing, configured-command parsing and refusals, the version floor, plugin hook lifecycle with stale-generation rejection, retirement paths, and the generated launch line with and without a configured command.
The live guard checks spawn, trust, autonomy, hooks, turn end, liveness, commit trailers, the idle composer, doorbell steering, slash-skill invocation, idle and busy interrupt, the background-shell follow-up, exit, and the trust-dialog signature.
Herdr, Zellij, Orca, and cmux were inspected through their backend-neutral delivery and key capability surfaces, all of which deliver Ctrl+C, but were not live-tested here.
A keyboard cancellation that bypasses `fm-control` leaves the last busy record until the next hook event.
No primary supervision guarantee is implied by these worker hooks.
